# p14

**Prompt:**
> I want to add email digests — daily summary of what happened in your workspace. Before you write anything, tell me what you'd need to decide. I've been burned by half-designed notification features before.

_Context: Adding a feature that touches the notification system_


## Candidates (7)

- **Prompt Inflation** [warn] — Each interruption's cost is paid by every user on every occurrence, while its benefit accrues only in the rare case it prevents; past a low frequency threshold users learn to dismiss the class reflexively, which destroys the signal value of the one prompt that mattered. TRIGGER: A diff adds a confirmation dialog, permission prompt, toast, banner, badge, or notification to a flow that already has one — or a spec's answer to a risk is "warn the user."
- **The Metric That Moves Alone** [warn] — A proxy metric that can rise without the underlying job being served will be optimized directly, because it is the thing that is measured and reported; the product then drifts toward whatever produces the number, and the gap between metric and job widens fastest exactly when the metric looks best. TRIGGER: A success criterion is a count that can increase while the underlying job goes unserved — events emitted, broadcasts sent, tool calls, DAU, sign-ups, page views — with no paired measure of whether the recipient acted on it.
- **Cold Start Ignored** [block] — Any product whose value comes from other people's content or presence is worthless to user one, so the acquisition funnel and the retention mechanism fight each other: every user you bring sees an empty room and leaves, and their departure makes the room emptier. The founders must manufacture the initial density by hand because no channel can outrun an empty product. TRIGGER: A spec for a feed, map, marketplace, roster, leaderboard, directory, team view, or any social surface, with no stated plan for what a first user or solo user sees.
- **Curated Demo Data** [warn] — Designs validated on hand-picked content encode assumptions about length, density, freshness, and correctness that real data violates on day one; the demo proves the layout, not the product, and the gap surfaces publicly at launch scale. TRIGGER: A design, screenshot, or demo uses seeded, curated, or short sample data; or a spec has no defined empty state, long-string, stale-data, error, and high-volume case for the surface being built.
- **Assistant That Interrupts** [warn] — A proactive helper must infer intent from weak signals, so its false-positive rate is high, and every false positive costs a competent user an interruption plus a dismissal. The novice's occasional benefit is charged to the expert on every session, and dismissal becomes the learned default. TRIGGER: A spec adds a proactive tip, coach mark, onboarding tour, suggestion popup, or AI assistant that appears without the user requesting it, based on inferred intent.
- **Product Line Sprawl** [warn] — Each additional surface, SKU, or entry point consumes maintenance, documentation, support, and decision bandwidth permanently, while the marginal one is almost always worse than the median — so average quality falls monotonically as count rises, and the team's best people are spread across things no one would start today. TRIGGER: The plan adds a new surface, product, SKU, CLI command, MCP tool, page, or entry point while existing ones are unfinished, unowned, or undocumented; a countable surface inventory grows.
- **Global Blast Radius** [block] — Treating rules, content, or config as "not code" routes it around the staged rollout that protects code, so a bad artifact reaches 100% of the fleet in one push. If the failure mode also prevents the machine from booting, there is no remote path to roll back. TRIGGER: A change shipping to all users, machines, or tenants simultaneously — or a data/config/rules/prompt/template update path that bypasses the canary and staged-rollout used for code.
