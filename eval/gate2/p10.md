# p10

**Prompt:**
> there's a bunch of dead code in src/legacy that I'm pretty sure nothing imports anymore. find what's actually unreferenced and delete it, but don't touch anything that has a test pointing at it

_Context: Cleaning up before opening the repo to a contractor_


## Candidates (2)

- **Chesterton's Dead Code** [block] — Code that appears unused is often reachable through a path nobody has in mind — an old flag, a stale server, a legacy client — so removing the guard while leaving the code, or reusing its switch for a new meaning, arms a landmine that only fires under partial deployment. TRIGGER: A diff that deletes or repurposes a feature flag, retry, guard clause, or branch labeled unused/deprecated/legacy without explaining what originally set it.
- **One-Way Door Misread** [block] — Anything external parties can build against — a public API, tool name, URL scheme, event type, wire field, file format — becomes unrevocable the moment someone depends on it, because the cost of removal is paid by them and shows up as broken trust rather than a rollback. Such decisions get made at the speed of a reversible one because the diff looks small. TRIGGER: A diff or spec publishes something external parties will depend on: a public API endpoint, an MCP or CLI tool name, an event type or enum value, a URL scheme, a config key, an on-disk or wire format.
