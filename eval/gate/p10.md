# p10

**Prompt:**
> there's a bunch of dead code in src/legacy that I'm pretty sure nothing imports anymore. find what's actually unreferenced and delete it, but don't touch anything that has a test pointing at it

_Context: Cleaning up before opening the repo to a contractor_


## Candidates (8, ranked by lexical match)

- **Chesterton's Dead Code** [block] — Code that appears unused is often reachable through a path nobody has in mind — an old flag, a stale server, a legacy client — so removing the guard while leaving the code, or reusing its switch for a new meaning, arms a landmine that only fires under partial deployment. TRIGGER: A diff that deletes or repurposes a feature flag, retry, guard clause, or branch labeled unused/deprecated/legacy without explaining what originally set it.
- **Exit Reason Assumed** [note] — Churn explanations default to the most legible variable — price, salary, performance — because it is the one already instrumented. The actual reasons are relational and only obtainable by asking, so the retention fix targets the wrong lever and produces no change, which is then read as the problem being intractable. TRIGGER: An explanation of attrition, churn, drop-off, or non-adoption asserts a cause (price, speed, missing feature) without citing anything the departed users or teammates actually said.
- **Segment-Blind PMF Survey** [warn] — The Sean Ellis 40% test averages across everyone who signed up, and a product with intense fit for a narrow segment plus indifference from tourists scores the same as a product nobody loves. The average hides the segment that would tell you what to build, so teams conclude they have no fit and pivot away from the users who actually had it. TRIGGER: A proposal to run the 40% test, NPS, or a satisfaction survey across the full user list, or a stated PMF/NPS number reported as one figure with no segment breakdown.
- **One Shell, Two Inputs** [warn] — Touch and pointer imply different target sizes, hover availability, gesture vocabularies, and discovery mechanics; a single interface tuned for both is tuned for neither, and hidden gestures that are natural on a tablet become undiscoverable on hardware with no edges to swipe. TRIGGER: A spec targets one UI across incompatible input modes or form factors — touch and mouse, mobile and desktop, TV and handheld — or introduces hover-dependent or edge-gesture affordances in a surface that must also work with the other input.
- **Pet Cluster Upgrade** [warn] — Infrastructure configured by hand and not committed anywhere has no record of what depends on what, so an upgrade that changes an implicit contract (a label, a default, a deprecated field) breaks something nobody can trace back. Recovery becomes archaeology under time pressure. TRIGGER: An in-place upgrade, version bump, or migration of infrastructure described as legacy, hand-built, one-off, or "the original" — or config applied manually rather than from version control.
- **Job Mistaken For Demographic** [note] — Segmenting by who the user is produces feature requests that correlate with the segment but explain nothing causal, so improvements aimed at the persona miss the situation that actually triggered the purchase. Two people in the same demographic hire the product for opposite jobs, and averaging them produces a product for neither. TRIGGER: Requirements are segmented by who the user is (role, persona, seniority, company size, 'founders vs engineers') rather than by the situation and task at the moment of use.
- **Boiling The Ocean** [block] — When v1 requires three or more unproven components to all work at once, the probability of shipping is the product of each part's odds, and no single part can be validated until the others exist. Learning is deferred until the whole thing is done, which is exactly when it is most expensive to be wrong. TRIGGER: A spec or plan lists three or more novel, unproven components (new runtime, new data model, new rendering surface, new protocol) that must all work before anything is usable.
- **Launch Without Load** [block] — Capacity assumptions that are never measured are wrong in the unsafe direction, because designers estimate from the intended usage rather than the arrival pattern. Load appears as a step function at launch, not a ramp, so the first real test is also the first outage. TRIGGER: A ship/launch date with no load or soak test in the plan, or a stated concurrency/throughput number that is an estimate rather than a measurement.
