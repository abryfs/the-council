# p11

**Prompt:**
> signup to first-action conversion is 22%. people create an account and then just... stop. I don't know if it's the empty state, the fact that we ask for a repo connection immediately, or something dumber. help me figure out what to look at first

_Context: Onboarding funnel is leaking and the founder can see it in the numbers_


## Candidates (8, ranked by lexical match)

- **Error Text From Inside** [warn] — A message written from the system's state names a condition the user has no model for and no action attached to; it is technically accurate and operationally useless, so the user's only remaining move is to ask a human or abandon the task. TRIGGER: A diff adds or changes user-visible error, empty, or status copy that names an internal condition (state names, error codes, subsystem names, exception text) instead of what failed plus one concrete action the user can take.
- **Skipping The Unscalable** [warn] — Automating the first-user experience before doing it by hand encodes your guesses about what users need into software, and the automation then hides the disconfirming evidence. Manual onboarding is not inefficiency; it is the only instrument fine-grained enough to find the problem that the metrics summarize away. TRIGGER: A plan to build self-serve signup, an onboarding wizard, an email drip, an in-app tour, or a help center before roughly ten users have been onboarded by a founder in person.
- **Cold Start Ignored** [block] — Any product whose value comes from other people's content or presence is worthless to user one, so the acquisition funnel and the retention mechanism fight each other: every user you bring sees an empty room and leaves, and their departure makes the room emptier. The founders must manufacture the initial density by hand because no channel can outrun an empty product. TRIGGER: A spec for a feed, map, marketplace, roster, leaderboard, directory, team view, or any social surface, with no stated plan for what a first user or solo user sees.
- **Piggyback Channel Ignored** [note] — Early on you cannot afford to create demand, only to intercept it, which means the cheapest first channel is wherever your users are already aggregated and transacting. Teams skip this because owned channels (blog, newsletter, own social account) feel more legitimate — but those start at zero audience and compound too slowly to survive the runway. TRIGGER: A GTM plan whose channel list contains only owned surfaces (own blog, own newsletter, own social account, own docs site) and names no existing venue, marketplace, forum, or community where the target users already gather.
- **Single Channel Concentration** [warn] — A channel that supplies most of your users has a ceiling set by audience size and a decay curve set by fatigue and competitive entry, and both arrive without warning. Because the channel is working, nobody funds a second experiment until the first one flattens — at which point there is no runway to discover the replacement. TRIGGER: A growth model that extrapolates the current dominant channel's conversion rate forward, or a plan where one channel already supplies most users and no second-channel experiment is funded and dated.
- **Curated Demo Data** [warn] — Designs validated on hand-picked content encode assumptions about length, density, freshness, and correctness that real data violates on day one; the demo proves the layout, not the product, and the gap surfaces publicly at launch scale. TRIGGER: A design, screenshot, or demo uses seeded, curated, or short sample data; or a spec has no defined empty state, long-string, stale-data, error, and high-volume case for the surface being built.
- **Adding People To A Late Thing** [warn] — New people on a late project consume the time of the people who know the system, and communication paths grow quadratically with headcount, so the near-term effect on a component with tight internal coupling is negative. Partitionable work is the exception, and the work that is late is rarely the partitionable kind. TRIGGER: A slipping deliverable is answered by assigning more engineers, more parallel agents, or more concurrent sessions to the same component or file set, rather than by cutting scope.
- **No Beachhead** [warn] — A message aimed at everyone is specific to no one, so it fails the only test that matters early: can one user explain it to the next user in a sentence. Without a defined first customer, price, channel, and objection-handling all become guesses, and there is no dense population in which word of mouth can propagate. TRIGGER: TAM-driven sizing, "for any team / any company / everyone who...", or a launch plan listing three or more personas with no ranking of which one ships first.
