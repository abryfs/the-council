# Request

> Should we build the team/multi-seat plan before launch or ship single-user first? Right now billing assumes one person per account and adding seats means touching auth, the invite flow, and the Stripe integration. I keep going back and forth. We have no paying customers yet.

_Context: Two weeks from a small launch, deciding what makes the cut_

---

## Relevant failure patterns (apply these; do not quote them back)

- **Foundation Before First User** [block] — Infrastructure built for a feature that does not exist has no consumer to falsify its design, so its interface is derived from imagination and calcifies before contact. The dependent feature then inherits constraints from a substrate that was never tested against the real requirement. TRIGGER: A spec adds infrastructure — an index, cache, schema, consolidation pass, worker, centroid set, router — whose only named consumer is a feature not yet built or validated.
- **Cold Start Ignored** [block] — Any product whose value comes from other people's content or presence is worthless to user one, so the acquisition funnel and the retention mechanism fight each other: every user you bring sees an empty room and leaves, and their departure makes the room emptier. The founders must manufacture the initial density by hand because no channel can outrun an empty product. TRIGGER: A spec for a feed, map, marketplace, roster, leaderboard, directory, team view, or any social surface, with no stated plan for what a first user or solo user sees.
- **Seat Pricing Punishes Adoption** [warn] — When a product's value rises with how many colleagues are on it but the price also rises per colleague, the buyer's rational move is to restrict the rollout — which starves the exact network effect the product depends on. The pricing model actively fights the product's mechanism, and the resulting low penetration reads to the team as weak demand. TRIGGER: A pricing page or spec charging per seat, per user, or per member for a product whose core value requires a whole team, or charging full price for read-only/viewer/observer roles.
