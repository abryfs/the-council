# p01

**Prompt the founder typed:**
> add a rate limiter to the /v1/invites endpoint. 20 per hour per team, return 429 with a retry-after header. use whatever's already in the middleware chain, don't pull in a new dep

_Context: Mid-build on an API, adding abuse protection before a small public beta_

For EACH set below, judge EACH pattern: is it genuinely relevant to this specific prompt — would surfacing it change or improve how an agent handles this request? Be strict. A pattern that is merely topically adjacent is NOT relevant.


## Set A

- **Seat Pricing Punishes Adoption** — When a product's value rises with how many colleagues are on it but the price also rises per colleague, the buyer's rational move is to restrict the rollout — which starves the exact network effect the product depends on. The pricing model actively fights the product's mechanism, and the resulting low penetration reads to the team as weak demand. TRIGGER: A pricing page or spec charging per seat, per user, or per member for a product whose core value requires a whole team, or charging full price for read-only/viewer/observer roles.
- **Discoverability Mistaken For Absence** — Users request features they cannot find, so a request queue reads as a gap list when it is often a findability report; building the requested thing a second time adds surface area without adding capability and makes the original even harder to find. TRIGGER: A ticket or spec proposes building a capability that may already exist somewhere in the product — "add a way to X," "users can't do Y" — without a check of whether X/Y already ships behind a menu, flag, or command.
- **Distributed Monolith** — Splitting a codebase into services that share a release cadence and shared libraries converts in-process function calls into network calls without decoupling deploys, so you pay partial-failure, latency, and operational cost while keeping every coupling you had. TRIGGER: A spec proposing a separate service, worker, repo, or deployable per entity/destination/integration, or a diff introducing an RPC boundary between two things that ship together.
- **Negative Unit Economics As Growth** — Pricing below variable cost makes every additional user a larger loss, which inverts the normal relationship between traction and survival — the growth metrics look spectacular precisely while the company is dying faster. "We'll fix margins with scale" only works when marginal cost falls with volume, which it does not for pass-through goods. TRIGGER: A pricing proposal with unlimited/all-you-can-eat framing, a price below the per-user infrastructure or fulfillment cost, or copy promising to monetize later via ads, data, or upsell.
- **Chesterton's Dead Code** — Code that appears unused is often reachable through a path nobody has in mind — an old flag, a stale server, a legacy client — so removing the guard while leaving the code, or reusing its switch for a new meaning, arms a landmine that only fires under partial deployment. TRIGGER: A diff that deletes or repurposes a feature flag, retry, guard clause, or branch labeled unused/deprecated/legacy without explaining what originally set it.
- **Relearning Tax Ignored** — In a product people use daily, the interface is a motor habit; moving things resets that habit for every existing user at once, so the cost is paid on day one by everyone while the benefit accrues slowly to newcomers who do not exist yet. The new-user gain almost never exceeds the aggregate relearning loss. TRIGGER: A spec reorganizes navigation, moves an existing feature to a new location, renames a primary action, or changes the information architecture of a product that already has habituated daily users.
- **Signifier Erasure** — Flattening removes borders, fills, and shadows — which are not decoration but the clickability cues users scan for — so the visual noise drops while the search cost rises; the page looks calmer in a screenshot and costs more per task in use. TRIGGER: A diff removes borders, background fills, underlines, or shadows from interactive elements, converts buttons to text/ghost buttons, or a spec asks to "make it cleaner / flatter / less chrome."
- **Single Channel Concentration** — A channel that supplies most of your users has a ceiling set by audience size and a decay curve set by fatigue and competitive entry, and both arrive without warning. Because the channel is working, nobody funds a second experiment until the first one flattens — at which point there is no runway to discover the replacement. TRIGGER: A growth model that extrapolates the current dominant channel's conversion rate forward, or a plan where one channel already supplies most users and no second-channel experiment is funded and dated.
- **Distribution As An Afterthought** — Product work has a legible feedback loop (ship, see it work) and distribution does not, so engineering-led teams spend the entire runway on the loop that feels productive and reach the market with no channel built. By the time distribution becomes urgent, the money that would have funded channel experiments is already spent on the product. TRIGGER: A roadmap, spec, or milestone list where every item is a product capability and no item names a specific acquisition channel, or a plan that says marketing/launch/GTM happens "after v1".
- **Interface Without A Contract** — When two components exchange bare numbers or strings, the meaning (unit, timezone, encoding, ID namespace) lives only in each side's head. Nothing at the boundary can detect disagreement, so the mismatch propagates as plausible-looking data instead of an error. TRIGGER: A new API field, event payload, or cross-team/cross-service boundary passing raw numbers, timestamps, identifiers, or strings with no shared type, unit, or validation at the boundary.
- **One-Way Door Misread** — Anything external parties can build against — a public API, tool name, URL scheme, event type, wire field, file format — becomes unrevocable the moment someone depends on it, because the cost of removal is paid by them and shows up as broken trust rather than a rollback. Such decisions get made at the speed of a reversible one because the diff looks small. TRIGGER: A diff or spec publishes something external parties will depend on: a public API endpoint, an MCP or CLI tool name, an event type or enum value, a URL scheme, a config key, an on-disk or wire format.
- **Innovation Token Overdraft** — Every unfamiliar technology carries unknown failure modes that only surface under production load, and each one consumes the same scarce resource: engineer attention during incidents. Spending several at once means every outage has multiple novel suspects and no one has intuition about any of them. TRIGGER: A diff or spec that introduces a new datastore, language, queue, or orchestration layer — especially two or more in the same change — where an already-running component would do.
- **Technology Seeking A Job** — When the differentiator is stated as a capability rather than a task someone was already trying to accomplish, the feature has no natural moment of use, so adoption requires teaching a new behavior instead of intercepting an existing one. Impressive capability and unused capability are fully compatible. TRIGGER: The spec leads with what the system can do ('we can embed / route / render / detect X') and the user's task appears only as a downstream illustration, or a hero feature has no named moment when someone would reach for it.
- **Second-System Effect** — The v2 becomes the dumping ground for every idea deferred from v1, and because none of them has shipped, none can be cut on evidence. Scope grows faster than the team can integrate, so the system never reaches a state where any single feature is finishable. TRIGGER: A spec or plan for a v2/next-gen version that lists features deferred from v1, or bundles a new data model + new UI + new extensibility layer in one release.
- **The Approval Bottleneck** — Centralizing a recurring decision in one person converts a throughput problem into a queue whose depth is invisible to the approver, who sees only the items they touched. Quality rises per item while the volume of items that never arrive — because the wait killed them — goes unmeasured. TRIGGER: A process or spec routes every instance of a recurring decision (hires, merges, deploys, copy changes, place bindings) through one named approver, with no delegation rule or bypass condition.

## Set B

- **Hype Ahead Of Usability** — A long, expert-narrated demo can make an unexplainable product look compelling to an audience primed to be impressed, and invite scarcity converts that impression into signups. Neither tests the actual constraint — whether one ordinary user can explain the product to the next one — so the waitlist converts into a cohort that opens it once and never returns. TRIGGER: A launch plan gated by waitlist or invite codes, or a demo script/video longer than about two minutes that requires narration to make the product legible.
- **Preference-First Framing** — When the decision-maker states their conclusion before soliciting input, every subsequent contribution is scored by the contributor against the cost of contradicting them, not against the evidence. Input arrives, so the process looks consultative, but it has been filtered to what survives disagreement with the boss. TRIGGER: A request to review, sign off on, or implement an approach whose author has already stated a preferred outcome, or a message shaped as "here's what we're doing — thoughts?"
- **Global Blast Radius** — Treating rules, content, or config as "not code" routes it around the staged rollout that protects code, so a bad artifact reaches 100% of the fleet in one push. If the failure mode also prevents the machine from booting, there is no remote path to roll back. TRIGGER: A change shipping to all users, machines, or tenants simultaneously — or a data/config/rules/prompt/template update path that bypasses the canary and staged-rollout used for code.
- **Metric As Taste Proxy** — Delegating small aesthetic judgments to experiments converts every decision into a measurement cost, and because micro-variants have micro-effects, the org optimizes a local hill it can measure while losing the ability to make any decision it cannot. Designers who supply judgment become unable to justify their work and leave. TRIGGER: A design disagreement is proposed to be settled by A/B test, click-through data, or "let's measure it" — particularly on typography, spacing, color, copy tone, or single-pixel values.
- **Numbers Nobody Measured** — A quantitative claim with no measurement behind it still functions as one downstream — it gets cited, budgeted against, and used to close arguments — because the number's format carries authority its provenance does not. Organizations generate these numbers where the desired answer is known and the measurement is expensive. TRIGGER: A spec, README, or marketing line quotes a reliability, latency, uptime, accuracy, or coverage figure without naming the measurement that produced it.
- **Trivial Transitive Dependency** — A dependency's risk is set by the reliability of its publishing and maintenance, not by its size, and transitive pulls mean the risky package is one nobody chose. Eleven lines of code can carry the same availability and supply-chain exposure as eleven thousand. TRIGGER: A diff adding a package to package.json, go.mod, requirements.txt, or Cargo.toml — especially a small single-purpose one, or one arriving transitively rather than being chosen.
- **One-Way Door, Casual** — Decisions get processed at the weight of their immediate cost, not their reversibility, so a cheap-to-decline strategic option receives less scrutiny than an expensive-to-build feature. The irreversibility only becomes visible after the window that would have let you act on it has closed. TRIGGER: A decision that forecloses a future option (a partnership declined, a public API committed, a naming/positioning lock, a data model that cannot be migrated) is being made in the same pass as routine work, with no note distinguishing it.
- **Channel-Price Mismatch** — A product's price point determines which acquisition channels can ever pay back; ad-based channels have a floor CAC set by auction competition, and if that floor exceeds the customer's lifetime contribution the channel is unusable at any spend level. Teams discover this after burning the test budget because they benchmarked click-through, not payback. TRIGGER: A GTM plan or budget line proposing Google/Meta/LinkedIn/Reddit ads, sponsorships, or outbound SDRs without stating ARPU, gross margin, and a payback period in months.
- **The Deck Instead Of The Memo** — Bullets let a proposal omit the connective tissue — the constraint, the alternative rejected, the thing that would make this wrong — because a bullet has no grammar that requires them. The gaps are invisible to the reader and often to the author, who mistakes the deck's completeness for the argument's. TRIGGER: A plan or spec arrives as a feature list, bullet outline, table, or phase grid with no prose section stating the problem, the constraints, and what evidence would falsify the approach.
- **Exit Reason Assumed** — Churn explanations default to the most legible variable — price, salary, performance — because it is the one already instrumented. The actual reasons are relational and only obtainable by asking, so the retention fix targets the wrong lever and produces no change, which is then read as the problem being intractable. TRIGGER: An explanation of attrition, churn, drop-off, or non-adoption asserts a cause (price, speed, missing feature) without citing anything the departed users or teammates actually said.
- **Automatic Failover Split-Brain** — Automated leader promotion cannot distinguish a dead primary from an unreachable one, so a brief network partition produces two writable primaries. The outage is then not the downtime but the reconciliation of divergent writes, which is manual and unbounded. TRIGGER: A design adding automatic failover, leader election, multi-region writes, or a health-check-driven promotion — or any mention of a heartbeat timeout that decides who is authoritative.
- **Motion Without An Exit** — Vestibular responses to large-field motion are physiological, not preferential — a transition that reads as delightful to most users induces genuine nausea and vertigo in a minority, and without a system-level opt-out those users cannot use the product at all. TRIGGER: A diff adds parallax, zoom transitions, autoplay, scroll-linked animation, or page transitions — and does not gate them behind prefers-reduced-motion or an equivalent user setting.
- **Preserving The Shape** — When a change is bolted onto an existing structure specifically to avoid disturbing it — because touching it would trigger a migration, recertification, or retraining cost — the new behavior inherits constraints it was never designed for, and the reason to avoid them becomes a reason not to fix them. TRIGGER: A change explicitly scoped to avoid touching an existing schema, interface, migration, or retraining/re-certification cost — phrases like "without changing the existing", "to avoid a migration", "keep it backward compatible" driving the design rather than following it.
- **Unlabeled Working Surface** — Surfaces "no user sees" — shell prompts, admin panels, log output, internal dashboards — are used by humans under time pressure, and identical-looking contexts there produce identity confusion at the exact moment stakes are highest. Unseen does not mean unused; it means untested. TRIGGER: Work touches an internal-only surface — CLI output, shell/SSH tooling, admin console, staging vs prod environment, log lines, migration scripts — and the change is justified as "internal, no design needed."
- **Skipping The Unscalable** — Automating the first-user experience before doing it by hand encodes your guesses about what users need into software, and the automation then hides the disconfirming evidence. Manual onboarding is not inefficiency; it is the only instrument fine-grained enough to find the problem that the metrics summarize away. TRIGGER: A plan to build self-serve signup, an onboarding wizard, an email drip, an in-app tour, or a help center before roughly ten users have been onboarded by a founder in person.

TRIGGER: A diff adds or changes user-visible error, empty, or status copy that names an internal condition (state names, error codes, subsystem names, exception text) instead of what failed plus one concrete action the user can take.

- **Reused Component, New Envelope** — A component's correctness depends on the operating envelope it was validated in — value ranges, clock rates, load profile. Reuse carries the code but not the envelope, and the assumption that made it safe becomes silently false. TRIGGER: A diff or plan that lifts an existing module, service, query, or library into a new scale, platform, region, or traffic profile described as reusing it "unchanged" or "as-is".
- **Two-Way Door Deliberated** — Applying heavyweight process to a reversible decision costs more than being wrong would have, and the delay itself removes the cheapest source of information — shipping it and watching. Organizations default to the heavy process for everything because the process was designed around the rare irreversible case. TRIGGER: An easily reversible change — copy, layout, a default value, ordering, a flag's initial setting, a threshold — is escalated to a spec, a review cycle, or a founder decision.
- **Launch Without Load** — Capacity assumptions that are never measured are wrong in the unsafe direction, because designers estimate from the intended usage rather than the arrival pattern. Load appears as a step function at launch, not a ramp, so the first real test is also the first outage. TRIGGER: A ship/launch date with no load or soak test in the plan, or a stated concurrency/throughput number that is an estimate rather than a measurement.
- **Alert As The Fix** — Adding a warning to an unactioned stream does not create action; it raises the base rate of ignorable signals, which lowers the probability that any specific one is investigated. The detection exists on paper and is absent in practice. TRIGGER: A proposed remediation that consists of logging a warning, emitting a metric, or adding a monitor — with no owner, threshold, or defined response — or a codebase with existing warnings nobody triages.
- **Guessing The Bottleneck** — Intuition about performance is trained on the code you read, while cost lives in behavior you cannot see — allocation, cache misses, scheduler and GC intervals, tail latency. Optimizing before profiling spends effort on the wrong axis and hides the real cause behind a changed baseline. TRIGGER: A diff or plan doing performance work — caching, batching, async, index, language/runtime swap — with no profile, benchmark, or production measurement cited, or a claim that something "should be faster".
- **Complected Convenience** — Braiding an extra capability into a general-purpose path means every caller of that path silently gains the capability, including callers handling attacker-controlled input. The convenience is opt-out by omission rather than opt-in by intent. TRIGGER: A change adding implicit behavior to a shared path: string interpolation, template evaluation, auto-deserialization, dynamic dispatch on user data, or a "helpful" default that triggers without being requested.
- **Statistics Against Trust** — Answering a reported defect with its probability treats the user's problem as frequency when the actual damage is to the belief that the product's outputs can be relied on without checking. The probability argument is usually correct and always escalates, because it tells the reporter their experience does not count. TRIGGER: A response to a user-reported bug, data-loss report, or wrong-output complaint leads with how rare the condition is, or proposes closing it as won't-fix on frequency grounds.
- **Preserving The Shape** — When a change is bolted onto an existing structure specifically to avoid disturbing it — because touching it would trigger a migration, recertification, or retraining cost — the new behavior inherits constraints it was never designed for, and the reason to avoid them becomes a reason not to fix them. - **Prompt Inflation** — Each interruption's cost is paid by every user on every occurrence, while its benefit accrues only in the rare case it prevents; past a low frequency threshold users learn to dismiss the class reflexively, which destroys the signal value of the one prompt that mattered. TRIGGER: A diff adds a confirmation dialog, permission prompt, toast, banner, badge, or notification to a flow that already has one — or a spec's answer to a risk is "warn the user."
