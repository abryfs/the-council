# p16

**Prompt the founder typed:**
> timestamps are showing up one day off for users in Australia. we store UTC and format client side with toLocaleDateString. find it

_Context: Small formatting bug reported by a user in a different timezone_

For EACH set below, judge EACH pattern: is it genuinely relevant to this specific prompt — would surfacing it change or improve how an agent handles this request? Be strict. A pattern that is merely topically adjacent is NOT relevant.


## Set A

- **Interface Without A Contract** — When two components exchange bare numbers or strings, the meaning (unit, timezone, encoding, ID namespace) lives only in each side's head. Nothing at the boundary can detect disagreement, so the mismatch propagates as plausible-looking data instead of an error. TRIGGER: A new API field, event payload, or cross-team/cross-service boundary passing raw numbers, timestamps, identifiers, or strings with no shared type, unit, or validation at the boundary.
- **Reused Component, New Envelope** — A component's correctness depends on the operating envelope it was validated in — value ranges, clock rates, load profile. Reuse carries the code but not the envelope, and the assumption that made it safe becomes silently false. TRIGGER: A diff or plan that lifts an existing module, service, query, or library into a new scale, platform, region, or traffic profile described as reusing it "unchanged" or "as-is".
- **Curated Demo Data** — Designs validated on hand-picked content encode assumptions about length, density, freshness, and correctness that real data violates on day one; the demo proves the layout, not the product, and the gap surfaces publicly at launch scale. TRIGGER: A design, screenshot, or demo uses seeded, curated, or short sample data; or a spec has no defined empty state, long-string, stale-data, error, and high-volume case for the surface being built.
- **Statistics Against Trust** — Answering a reported defect with its probability treats the user's problem as frequency when the actual damage is to the belief that the product's outputs can be relied on without checking. The probability argument is usually correct and always escalates, because it tells the reporter their experience does not count. TRIGGER: A response to a user-reported bug, data-loss report, or wrong-output complaint leads with how rare the condition is, or proposes closing it as won't-fix on frequency grounds.
- **Root Cause Singular** — Five-whys terminates at the first cause that is both technical and fixable, because that node is where the search stops feeling productive. The organizational conditions that let the technical fault reach production are upstream of that stopping point, so they survive the fix and reproduce it. TRIGGER: An incident writeup, postmortem, or bug analysis names exactly one root cause and one code-level fix, with no finding about how the defect passed review or shipped.
- **Guessing The Bottleneck** — Intuition about performance is trained on the code you read, while cost lives in behavior you cannot see — allocation, cache misses, scheduler and GC intervals, tail latency. Optimizing before profiling spends effort on the wrong axis and hides the real cause behind a changed baseline. TRIGGER: A diff or plan doing performance work — caching, batching, async, index, language/runtime swap — with no profile, benchmark, or production measurement cited, or a claim that something "should be faster".
- **Numbers Nobody Measured** — A quantitative claim with no measurement behind it still functions as one downstream — it gets cited, budgeted against, and used to close arguments — because the number's format carries authority its provenance does not. Organizations generate these numbers where the desired answer is known and the measurement is expensive. TRIGGER: A spec, README, or marketing line quotes a reliability, latency, uptime, accuracy, or coverage figure without naming the measurement that produced it.
- **Chesterton's Dead Code** — Code that appears unused is often reachable through a path nobody has in mind — an old flag, a stale server, a legacy client — so removing the guard while leaving the code, or reusing its switch for a new meaning, arms a landmine that only fires under partial deployment. TRIGGER: A diff that deletes or repurposes a feature flag, retry, guard clause, or branch labeled unused/deprecated/legacy without explaining what originally set it.
- **Unlabeled Working Surface** — Surfaces "no user sees" — shell prompts, admin panels, log output, internal dashboards — are used by humans under time pressure, and identical-looking contexts there produce identity confusion at the exact moment stakes are highest. Unseen does not mean unused; it means untested. TRIGGER: Work touches an internal-only surface — CLI output, shell/SSH tooling, admin console, staging vs prod environment, log lines, migration scripts — and the change is justified as "internal, no design needed."
- **Error Text From Inside** — A message written from the system's state names a condition the user has no model for and no action attached to; it is technically accurate and operationally useless, so the user's only remaining move is to ask a human or abandon the task. TRIGGER: A diff adds or changes user-visible error, empty, or status copy that names an internal condition (state names, error codes, subsystem names, exception text) instead of what failed plus one concrete action the user can take.
- **Silent Mode Divergence** — When one control's meaning depends on a mode the user cannot see at the moment of input, the interface accepts a correct-looking action and executes a different one; the operator's mental model and the machine's state diverge with no feedback to reconcile them. TRIGGER: A diff or spec adds a mode, toggle, view-state, or context in which the same control, keystroke, or input field produces different results — especially when the current mode is shown somewhere other than where the input happens.
- **One Shell, Two Inputs** — Touch and pointer imply different target sizes, hover availability, gesture vocabularies, and discovery mechanics; a single interface tuned for both is tuned for neither, and hidden gestures that are natural on a tablet become undiscoverable on hardware with no edges to swipe. TRIGGER: A spec targets one UI across incompatible input modes or form factors — touch and mouse, mobile and desktop, TV and handheld — or introduces hover-dependent or edge-gesture affordances in a surface that must also work with the other input.
- **Preserving The Shape** — When a change is bolted onto an existing structure specifically to avoid disturbing it — because touching it would trigger a migration, recertification, or retraining cost — the new behavior inherits constraints it was never designed for, and the reason to avoid them becomes a reason not to fix them. TRIGGER: A change explicitly scoped to avoid touching an existing schema, interface, migration, or retraining/re-certification cost — phrases like "without changing the existing", "to avoid a migration", "keep it backward compatible" driving the design rather than following it.
- **Alert As The Fix** — Adding a warning to an unactioned stream does not create action; it raises the base rate of ignorable signals, which lowers the probability that any specific one is investigated. The detection exists on paper and is absent in practice. TRIGGER: A proposed remediation that consists of logging a warning, emitting a metric, or adding a monitor — with no owner, threshold, or defined response — or a codebase with existing warnings nobody triages.
- **Two-Way Door Deliberated** — Applying heavyweight process to a reversible decision costs more than being wrong would have, and the delay itself removes the cheapest source of information — shipping it and watching. Organizations default to the heavy process for everything because the process was designed around the rare irreversible case. TRIGGER: An easily reversible change — copy, layout, a default value, ordering, a flag's initial setting, a threshold — is escalated to a spec, a review cycle, or a founder decision.

## Set B

- **CAC Buried In COGS** — When customers churn faster than they repay acquisition cost, acquisition spend stops being an investment and becomes a recurring cost of goods — every dollar of revenue requires a fresh dollar of marketing forever. Reporting new-customer counts instead of cohort curves hides this, because the top line grows right up until spend stops. TRIGGER: A growth dashboard, OKR, or investor update whose headline metric is signups, downloads, trials, or new customers, with no cohort retention curve or LTV:CAC ratio alongside it.
- **Feature Parity Positioning** — Positioning your product as a better version of an incumbent asks the customer to compare on the incumbent's chosen axes, where the incumbent's scale wins by construction, and it gives no one a reason to bear switching cost. Parity is also unbounded work: matching the feature list is a treadmill the incumbent sets the speed of. TRIGGER: A positioning doc, landing page, or spec that frames the product as "X but better/faster/cheaper", or leads with a feature-comparison table against a named incumbent.
- **Native Control Replacement** — Platform controls carry years of accumulated behavior — keyboard, IME, screen readers, touch targets, zoom, autofill — that is invisible in the visual spec; a custom reimplementation reproduces the appearance and silently drops the behavior, and the loss shows up only for users you are not. TRIGGER: A diff replaces a native element (select, date input, file input, scrollbar, checkbox, alert) with a custom component, or a design spec styles a control in a way only achievable by rebuilding it.
- **Reused Component, New Envelope** — A component's correctness depends on the operating envelope it was validated in — value ranges, clock rates, load profile. Reuse carries the code but not the envelope, and the assumption that made it safe becomes silently false. TRIGGER: A diff or plan that lifts an existing module, service, query, or library into a new scale, platform, region, or traffic profile described as reusing it "unchanged" or "as-is".
- **Funding As Distribution** — A funding announcement and its press cycle produce a one-time spike of curious non-customers, which the team reads as demand and uses to justify skipping channel-building. Press has no compounding mechanism — it cannot be re-run — so the traffic decays to zero while the burn rate raised to match the ambition does not. TRIGGER: A launch plan whose top-of-funnel is press coverage, a funding announcement, an influencer/analyst push, or a Product Hunt / HN / Show HN day, with no channel that keeps producing users on day 30.
- **Discoverability Mistaken For Absence** — Users request features they cannot find, so a request queue reads as a gap list when it is often a findability report; building the requested thing a second time adds surface area without adding capability and makes the original even harder to find. TRIGGER: A ticket or spec proposes building a capability that may already exist somewhere in the product — "add a way to X," "users can't do Y" — without a check of whether X/Y already ships behind a menu, flag, or command.
- **Growth Before Retention** — Acquisition spend against a leaky product buys a number, not a business: each cohort churns at the same rate, so the spend must repeat forever, and headcount and infrastructure scale to the peak while revenue scales to the retained fraction. The growth curve also hides the retention problem from the people funding it. TRIGGER: A plan proposes launch, marketing, headcount, or scale spend while retention, repeat usage, or activation is unmeasured, known-bad, or measured on a single cohort.
- **Cold Start Ignored** — Any product whose value comes from other people's content or presence is worthless to user one, so the acquisition funnel and the retention mechanism fight each other: every user you bring sees an empty room and leaves, and their departure makes the room emptier. The founders must manufacture the initial density by hand because no channel can outrun an empty product. TRIGGER: A spec for a feed, map, marketplace, roster, leaderboard, directory, team view, or any social surface, with no stated plan for what a first user or solo user sees.
- **Product Line Sprawl** — Each additional surface, SKU, or entry point consumes maintenance, documentation, support, and decision bandwidth permanently, while the marginal one is almost always worse than the median — so average quality falls monotonically as count rises, and the team's best people are spread across things no one would start today. TRIGGER: The plan adds a new surface, product, SKU, CLI command, MCP tool, page, or entry point while existing ones are unfinished, unowned, or undocumented; a countable surface inventory grows.
- **Skipping The Unscalable** — Automating the first-user experience before doing it by hand encodes your guesses about what users need into software, and the automation then hides the disconfirming evidence. Manual onboarding is not inefficiency; it is the only instrument fine-grained enough to find the problem that the metrics summarize away. TRIGGER: A plan to build self-serve signup, an onboarding wizard, an email drip, an in-app tour, or a help center before roughly ten users have been onboarded by a founder in person.
- **Job Mistaken For Demographic** — Segmenting by who the user is produces feature requests that correlate with the segment but explain nothing causal, so improvements aimed at the persona miss the situation that actually triggered the purchase. Two people in the same demographic hire the product for opposite jobs, and averaging them produces a product for neither. TRIGGER: Requirements are segmented by who the user is (role, persona, seniority, company size, 'founders vs engineers') rather than by the situation and task at the moment of use.
- **Sunk Identity** — A decision defended by prior investment or by "this is what we are" cannot be evaluated, because both premises are facts about the past rather than about the option. The incumbent option gets an unearned advantage precisely in proportion to how much was spent establishing it. TRIGGER: A decision or spec is defended by how much has already been built, how long it took, or by identity language ("we're a X company", "this is our thesis"), rather than by the option's forward value.
- **Numbers Nobody Measured** — A quantitative claim with no measurement behind it still functions as one downstream — it gets cited, budgeted against, and used to close arguments — because the number's format carries authority its provenance does not. Organizations generate these numbers where the desired answer is known and the measurement is expensive. TRIGGER: A spec, README, or marketing line quotes a reliability, latency, uptime, accuracy, or coverage figure without naming the measurement that produced it.
- **Beautiful Prototype Bias** — Perceived usability tracks aesthetics more tightly than actual usability, so a polished mock or prototype scores well in review and testing regardless of whether the interaction works; the visual finish suppresses exactly the criticism the review exists to surface. TRIGGER: A design is approved from a high-fidelity mock, Figma prototype, or rendered screenshot; or usability testing is run on a visually finished build without a low-fidelity or degraded-data comparison.
- **Curated Demo Data** — Designs validated on hand-picked content encode assumptions about length, density, freshness, and correctness that real data violates on day one; the demo proves the layout, not the product, and the gap surfaces publicly at launch scale. TRIGGER: A design, screenshot, or demo uses seeded, curated, or short sample data; or a spec has no defined empty state, long-string, stale-data, error, and high-volume case for the surface being built.

## Set C

- **Built On Rented Land** — A distribution channel owned by another company is revocable on their schedule, and they revoke it exactly when you become large enough to matter or when they want the market themselves. The dependency is invisible during the growth phase because the channel is working, which is the same evidence that makes you a threat. TRIGGER: A growth mechanism that depends on another company's API, social graph, app-store placement, feed distribution, marketplace listing, extension store, or OAuth integration as the primary source of new users.
- **Interface Without A Contract** — When two components exchange bare numbers or strings, the meaning (unit, timezone, encoding, ID namespace) lives only in each side's head. Nothing at the boundary can detect disagreement, so the mismatch propagates as plausible-looking data instead of an error. TRIGGER: A new API field, event payload, or cross-team/cross-service boundary passing raw numbers, timestamps, identifiers, or strings with no shared type, unit, or validation at the boundary.
- **Funding As Distribution** — A funding announcement and its press cycle produce a one-time spike of curious non-customers, which the team reads as demand and uses to justify skipping channel-building. TRIGGER: A launch plan whose top-of-funnel is press coverage, a funding announcement, an influencer/analyst push, or a Product Hunt / HN / Show HN day, with no channel that keeps producing users on day 30.
- **Silent Room Consensus** — Silence in a decision meeting is recorded as agreement, but it is more often the cost of dissent exceeding its expected payoff — one person's objection cannot beat an apparently settled room, so no one pays. The group then treats the absence of objection as independent corroboration it never received. TRIGGER: A prompt or doc asserts "the team is aligned", "no objections were raised", or "we all agreed" without naming a specific person who argued the other side and what they said.
- **One-Way Door Misread** — Anything external parties can build against — a public API, tool name, URL scheme, event type, wire field, file format — becomes unrevocable the moment someone depends on it, because the cost of removal is paid by them and shows up as broken trust rather than a rollback. Such decisions get made at the speed of a reversible one because the diff looks small. TRIGGER: A diff or spec publishes something external parties will depend on: a public API endpoint, an MCP or CLI tool name, an event type or enum value, a URL scheme, a config key, an on-disk or wire format.
- **Discoverability Mistaken For Absence** — Users request features they cannot find, so a request queue reads as a gap list when it is often a findability report; building the requested thing a second time adds surface area without adding capability and makes the original even harder to find. TRIGGER: A ticket or spec proposes building a capability that may already exist somewhere in the product — "add a way to X," "users can't do Y" — without a check of whether X/Y already ships behind a menu, flag, or command.
- **The Big-Bang Relaunch** — Replacing a shipped surface wholesale in one release couples a hundred independent bets into a single irreversible event, so you cannot tell which change caused the loss, and existing users pay the full re-learning cost on a day they did not choose. Habitual users are the ones who notice most, and they are the ones you can least afford to lose. TRIGGER: A plan replaces an existing shipped surface in one release — 'v2 replaces v1', 'retire the old frame', 'cut over' — with no dual-run, opt-in, or staged migration.
- **Relearning Tax Ignored** — In a product people use daily, the interface is a motor habit; moving things resets that habit for every existing user at once, so the cost is paid on day one by everyone while the benefit accrues slowly to newcomers who do not exist yet. The new-user gain almost never exceeds the aggregate relearning loss. TRIGGER: A spec reorganizes navigation, moves an existing feature to a new location, renames a primary action, or changes the information architecture of a product that already has habituated daily users.
- **Skipping The Unscalable** — Automating the first-user experience before doing it by hand encodes your guesses about what users need into software, and the automation then hides the disconfirming evidence. Manual onboarding is not inefficiency; it is the only instrument fine-grained enough to find the problem that the metrics summarize away. TRIGGER: A plan to build self-serve signup, an onboarding wizard, an email drip, an in-app tour, or a help center before roughly ten users have been onboarded by a founder in person.
- **Paid Launch Without A Loop** — Advertising rents attention; it does not build any mechanism whereby one user produces the next. Without an in-product loop (sharing, referral, invite, content, SEO surface), the acquisition curve is a linear function of spend with no residual, so growth stops the instant the budget does — and the ad spend never revealed whether anyone would have come organically. TRIGGER: A GTM plan with a large paid media budget, a launch-day ad buy, or a campaign brief, where no line item describes an in-product mechanism that generates the next user.
- **Numbers Nobody Measured** — A quantitative claim with no measurement behind it still functions as one downstream — it gets cited, budgeted against, and used to close arguments — because the number's format carries authority its provenance does not. Organizations generate these numbers where the desired answer is known and the measurement is expensive. TRIGGER: A spec, README, or marketing line quotes a reliability, latency, uptime, accuracy, or coverage figure without naming the measurement that produced it.
- **Org Chart Shipped To Users** — A split that mirrors an internal boundary — separate app, brand, login, repo, or team — makes users pay the cost of a structure that exists for the builders' convenience. Users experience one job; splitting it forces them to re-onboard into a second product to accomplish what was previously one motion. TRIGGER: A split, rename, or separation in the product mirrors an internal boundary (two teams, two repos, two services, two panes) and forces the user to move between surfaces to complete one task.
- **Single Channel Concentration** — A channel that supplies most of your users has a ceiling set by audience size and a decay curve set by fatigue and competitive entry, and both arrive without warning. Because the channel is working, nobody funds a second experiment until the first one flattens — at which point there is no runway to discover the replacement. TRIGGER: A growth model that extrapolates the current dominant channel's conversion rate forward, or a plan where one channel already supplies most users and no second-channel experiment is funded and dated.
