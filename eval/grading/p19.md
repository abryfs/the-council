# p19

**Prompt the founder typed:**
> we've been free for 3 months and I've been too scared to put a price on it. 30ish active users, a handful use it daily. Should I start charging now, and if so how do I not lose the people who are actually using it?

_Context: Deciding whether to charge, weeks after a free beta started_

For EACH set below, judge EACH pattern: is it genuinely relevant to this specific prompt — would surfacing it change or improve how an agent handles this request? Be strict. A pattern that is merely topically adjacent is NOT relevant.


## Set A

- **Prompt Inflation** — Each interruption's cost is paid by every user on every occurrence, while its benefit accrues only in the rare case it prevents; past a low frequency threshold users learn to dismiss the class reflexively, which destroys the signal value of the one prompt that mattered. TRIGGER: A diff adds a confirmation dialog, permission prompt, toast, banner, badge, or notification to a flow that already has one — or a spec's answer to a risk is "warn the user."
- **Channel-Price Mismatch** — A product's price point determines which acquisition channels can ever pay back; ad-based channels have a floor CAC set by auction competition, and if that floor exceeds the customer's lifetime contribution the channel is unusable at any spend level. Teams discover this after burning the test budget because they benchmarked click-through, not payback. TRIGGER: A GTM plan or budget line proposing Google/Meta/LinkedIn/Reddit ads, sponsorships, or outbound SDRs without stating ARPU, gross margin, and a payback period in months.
- **Global Blast Radius** — Treating rules, content, or config as "not code" routes it around the staged rollout that protects code, so a bad artifact reaches 100% of the fleet in one push. If the failure mode also prevents the machine from booting, there is no remote path to roll back. TRIGGER: A change shipping to all users, machines, or tenants simultaneously — or a data/config/rules/prompt/template update path that bypasses the canary and staged-rollout used for code.
- **The Inside-View Estimate** — An estimate built by decomposing the specific task counts only the steps you can currently see, and the steps you cannot see are exactly the ones that consume the schedule. Decomposition feels more rigorous than a base rate, so it displaces the base rate rather than being checked against it. TRIGGER: A plan, spec, or roadmap states a duration, ship date, or phase count derived by listing the work, with no reference to how long a comparable past effort actually took.
- **Hype Ahead Of Usability** — A long, expert-narrated demo can make an unexplainable product look compelling to an audience primed to be impressed, and invite scarcity converts that impression into signups. Neither tests the actual constraint — whether one ordinary user can explain the product to the next one — so the waitlist converts into a cohort that opens it once and never returns. TRIGGER: A launch plan gated by waitlist or invite codes, or a demo script/video longer than about two minutes that requires narration to make the product legible.
- **Preference-First Framing** — When the decision-maker states their conclusion before soliciting input, every subsequent contribution is scored by the contributor against the cost of contradicting them, not against the evidence. Input arrives, so the process looks consultative, but it has been filtered to what survives disagreement with the boss. TRIGGER: A request to review, sign off on, or implement an approach whose author has already stated a preferred outcome, or a message shaped as "here's what we're doing — thoughts?"
- **Preserving The Shape** — When a change is bolted onto an existing structure specifically to avoid disturbing it — because touching it would trigger a migration, recertification, or retraining cost — the new behavior inherits constraints it was never designed for, and the reason to avoid them becomes a reason not to fix them. TRIGGER: A change explicitly scoped to avoid touching an existing schema, interface, migration, or retraining/re-certification cost — phrases like "without changing the existing", "to avoid a migration", "keep it backward compatible" driving the design rather than following it.
- **Numbers Nobody Measured** — A quantitative claim with no measurement behind it still functions as one downstream — it gets cited, budgeted against, and used to close arguments — because the number's format carries authority its provenance does not. Organizations generate these numbers where the desired answer is known and the measurement is expensive. TRIGGER: A spec, README, or marketing line quotes a reliability, latency, uptime, accuracy, or coverage figure without naming the measurement that produced it.
- **Error Text From Inside** — A message written from the system's state names a condition the user has no model for and no action attached to; it is technically accurate and operationally useless, so the user's only remaining move is to ask a human or abandon the task. TRIGGER: A diff adds or changes user-visible error, empty, or status copy that names an internal condition (state names, error codes, subsystem names, exception text) instead of what failed plus one concrete action the user can take.
- **Automatic Failover Split-Brain** — Automated leader promotion cannot distinguish a dead primary from an unreachable one, so a brief network partition produces two writable primaries. The outage is then not the downtime but the reconciliation of divergent writes, which is manual and unbounded. TRIGGER: A design adding automatic failover, leader election, multi-region writes, or a health-check-driven promotion — or any mention of a heartbeat timeout that decides who is authoritative.
- **Accessibility As Post-Ship Bug** — Accessibility is decided by structure — semantics, focus order, names, contrast — which is fixed at the moment the component is built; deferring it converts a design constraint into a rewrite, and in many jurisdictions into legal exposure that no backlog priority can defer. TRIGGER: A spec or diff ships an interactive component with a11y noted as follow-up, or introduces custom interactive markup (div-as-button, custom modal, canvas UI, drag-and-drop) with no keyboard path, focus management, or accessible name.
- **Premature Scaling** — Capacity built ahead of demand converts fixed costs into a deadline: the burn rate now sets how long you have to find the demand, rather than the demand setting how much you build. Because the capacity is sunk, the team also loses the option to change the shape of the business when the early signal comes back wrong. TRIGGER: A plan that adds headcount, geographies, warehouses, regions, or provisioned infrastructure capacity on a schedule rather than in response to a measured demand signal; "build it so it scales to N" before N/100 exists.
- **The Metric That Moves Alone** — A proxy metric that can rise without the underlying job being served will be optimized directly, because it is the thing that is measured and reported; the product then drifts toward whatever produces the number, and the gap between metric and job widens fastest exactly when the metric looks best. TRIGGER: A success criterion is a count that can increase while the underlying job goes unserved — events emitted, broadcasts sent, tool calls, DAU, sign-ups, page views — with no paired measure of whether the recipient acted on it.
- **Interface Without A Contract** — When two components exchange bare numbers or strings, the meaning (unit, timezone, encoding, ID namespace) lives only in each side's head. Nothing at the boundary can detect disagreement, so the mismatch propagates as plausible-looking data instead of an error. TRIGGER: A new API field, event payload, or cross-team/cross-service boundary passing raw numbers, timestamps, identifiers, or strings with no shared type, unit, or validation at the boundary.
- **No Beachhead** — A message aimed at everyone is specific to no one, so it fails the only test that matters early: can one user explain it to the next user in a sentence. Without a defined first customer, price, channel, and objection-handling all become guesses, and there is no dense population in which word of mouth can propagate. TRIGGER: TAM-driven sizing, "for any team / any company / everyone who...", or a launch plan listing three or more personas with no ranking of which one ships first.

## Set B

- **Free Tier With No Wall** — A free plan converts only where its limit sits exactly at the point a serious user becomes dependent; limits on axes casual users never hit (storage, history, time) give away the whole product and leave the paid tier selling nothing. Fixing this later means taking something back from existing users, which is a far more expensive act than setting the wall correctly at launch. TRIGGER: A spec adding a free plan, free tier, or open beta whose limits are storage, seats-of-one, retention window, or time, rather than the specific capability a committed user cannot work without; also any "free forever" framing.
- **Retroactive Value-Metric Change** — Customers price their own business models on your billing unit; changing that unit — especially applying it to work already shipped — invalidates their planning and reads as a breach rather than a price rise. The revolt costs more in trust and churn than the new revenue was ever worth, because the affected customers are by definition your most successful ones. TRIGGER: A pricing change that alters the billing unit (seats→usage, revenue→installs, flat→metered), reprices existing contracts, or applies to activity that already happened.
- **Segment-Blind PMF Survey** — The Sean Ellis 40% test averages across everyone who signed up, and a product with intense fit for a narrow segment plus indifference from tourists scores the same as a product nobody loves. The average hides the segment that would tell you what to build, so teams conclude they have no fit and pivot away from the users who actually had it. TRIGGER: A proposal to run the 40% test, NPS, or a satisfaction survey across the full user list, or a stated PMF/NPS number reported as one figure with no segment breakdown.
- **Exit Reason Assumed** — Churn explanations default to the most legible variable — price, salary, performance — because it is the one already instrumented. The actual reasons are relational and only obtainable by asking, so the retention fix targets the wrong lever and produces no change, which is then read as the problem being intractable. TRIGGER: An explanation of attrition, churn, drop-off, or non-adoption asserts a cause (price, speed, missing feature) without citing anything the departed users or teammates actually said.
- **Skipping The Unscalable** — Automating the first-user experience before doing it by hand encodes your guesses about what users need into software, and the automation then hides the disconfirming evidence. Manual onboarding is not inefficiency; it is the only instrument fine-grained enough to find the problem that the metrics summarize away. TRIGGER: A plan to build self-serve signup, an onboarding wizard, an email drip, an in-app tour, or a help center before roughly ten users have been onboarded by a founder in person.
- **Negative Unit Economics As Growth** — Pricing below variable cost makes every additional user a larger loss, which inverts the normal relationship between traction and survival — the growth metrics look spectacular precisely while the company is dying faster. "We'll fix margins with scale" only works when marginal cost falls with volume, which it does not for pass-through goods. TRIGGER: A pricing proposal with unlimited/all-you-can-eat framing, a price below the per-user infrastructure or fulfillment cost, or copy promising to monetize later via ads, data, or upsell.
- **Seat Pricing Punishes Adoption** — When a product's value rises with how many colleagues are on it but the price also rises per colleague, the buyer's rational move is to restrict the rollout — which starves the exact network effect the product depends on. The pricing model actively fights the product's mechanism, and the resulting low penetration reads to the team as weak demand. TRIGGER: A pricing page or spec charging per seat, per user, or per member for a product whose core value requires a whole team, or charging full price for read-only/viewer/observer roles.
- **One-Way Door, Casual** — Decisions get processed at the weight of their immediate cost, not their reversibility, so a cheap-to-decline strategic option receives less scrutiny than an expensive-to-build feature. The irreversibility only becomes visible after the window that would have let you act on it has closed. TRIGGER: A decision that forecloses a future option (a partnership declined, a public API committed, a naming/positioning lock, a data model that cannot be migrated) is being made in the same pass as routine work, with no note distinguishing it.
- **Growth Before Retention** — Acquisition spend against a leaky product buys a number, not a business: each cohort churns at the same rate, so the spend must repeat forever, and headcount and infrastructure scale to the peak while revenue scales to the retained fraction. The growth curve also hides the retention problem from the people funding it. TRIGGER: A plan proposes launch, marketing, headcount, or scale spend while retention, repeat usage, or activation is unmeasured, known-bad, or measured on a single cohort.
- **CAC Buried In COGS** — When customers churn faster than they repay acquisition cost, acquisition spend stops being an investment and becomes a recurring cost of goods — every dollar of revenue requires a fresh dollar of marketing forever. Reporting new-customer counts instead of cohort curves hides this, because the top line grows right up until spend stops. TRIGGER: A growth dashboard, OKR, or investor update whose headline metric is signups, downloads, trials, or new customers, with no cohort retention curve or LTV:CAC ratio alongside it.
- **Channel-Price Mismatch** — A product's price point determines which acquisition channels can ever pay back; ad-based channels have a floor CAC set by auction competition, and if that floor exceeds the customer's lifetime contribution the channel is unusable at any spend level. Teams discover this after burning the test budget because they benchmarked click-through, not payback. TRIGGER: A GTM plan or budget line proposing Google/Meta/LinkedIn/Reddit ads, sponsorships, or outbound SDRs without stating ARPU, gross margin, and a payback period in months.
- **Undifferentiated Price War** — Competing on a dimension your rival can copy within a week converts the whole category's margin into customer subsidy, and both sides must keep spending to hold position they can never win. The winner is whoever has more capital, not whoever built the better product. TRIGGER: The plan competes on price, free-tier size, limits, discounting, or speed of copying a feature, in a market where a funded competitor can match the move immediately.
- **Positioning To The Wrong Frame** — The category you claim determines which competitors the buyer mentally lines you up against and which features they treat as table stakes. Claim a broad, incumbent-owned category and your genuine differentiator is scored as a minor feature; claim the frame where that differentiator is the whole point and the same product becomes the obvious choice. TRIGGER: Copy or a spec that names a broad established category ("CRM", "project management", "observability", "coordination layer") without naming the specific buyer and the specific alternative they'd otherwise use.
- **Two-Way Door Deliberated** — Applying heavyweight process to a reversible decision costs more than being wrong would have, and the delay itself removes the cheapest source of information — shipping it and watching. Organizations default to the heavy process for everything because the process was designed around the rare irreversible case. TRIGGER: An easily reversible change — copy, layout, a default value, ordering, a flag's initial setting, a threshold — is escalated to a spec, a review cycle, or a founder decision.
- **No Beachhead** — A message aimed at everyone is specific to no one, so it fails the only test that matters early: can one user explain it to the next user in a sentence. Without a defined first customer, price, channel, and objection-handling all become guesses, and there is no dense population in which word of mouth can propagate. TRIGGER: TAM-driven sizing, "for any team / any company / everyone who...", or a launch plan listing three or more personas with no ranking of which one ships first.

## Set C

- **Relearning Tax Ignored** — In a product people use daily, the interface is a motor habit; moving things resets that habit for every existing user at once, so the cost is paid on day one by everyone while the benefit accrues slowly to newcomers who do not exist yet. The new-user gain almost never exceeds the aggregate relearning loss. TRIGGER: A spec reorganizes navigation, moves an existing feature to a new location, renames a primary action, or changes the information architecture of a product that already has habituated daily users.
- **Seat Pricing Punishes Adoption** — When a product's value rises with how many colleagues are on it but the price also rises per colleague, the buyer's rational move is to restrict the rollout — which starves the exact network effect the product depends on. The pricing model actively fights the product's mechanism, and the resulting low penetration reads to the team as weak demand. TRIGGER: A pricing page or spec charging per seat, per user, or per member for a product whose core value requires a whole team, or charging full price for read-only/viewer/observer roles.

The actual reasons are relational and only obtainable by asking, so the retention fix targets the wrong lever and produces no change, which is then read as the problem being intractable. TRIGGER: An explanation of attrition, churn, drop-off, or non-adoption asserts a cause (price, speed, missing feature) without citing anything the departed users or teammates actually said.

TRIGGER: A GTM plan or budget line proposing Google/Meta/LinkedIn/Reddit ads, sponsorships, or outbound SDRs without stating ARPU, gross margin, and a payback period in months.
- **Job Mistaken For Demographic** — Segmenting by who the user is produces feature requests that correlate with the segment but explain nothing causal, so improvements aimed at the persona miss the situation that actually triggered the purchase. Two people in the same demographic hire the product for opposite jobs, and averaging them produces a product for neither. TRIGGER: Requirements are segmented by who the user is (role, persona, seniority, company size, 'founders vs engineers') rather than by the situation and task at the moment of use.
- **Free Tier With No Wall** — A free plan converts only where its limit sits exactly at the point a serious user becomes dependent; limits on axes casual users never hit (storage, history, time) give away the whole product and leave the paid tier selling nothing. Fixing this later means taking something back from existing users, which is a far more expensive act than setting the wall correctly at launch. TRIGGER: A spec adding a free plan, free tier, or open beta whose limits are storage, seats-of-one, retention window, or time, rather than the specific capability a committed user cannot work without; also any "free forever" framing.
- **Cold Start Ignored** — Any product whose value comes from other people's content or presence is worthless to user one, so the acquisition funnel and the retention mechanism fight each other: every user you bring sees an empty room and leaves, and their departure makes the room emptier. The founders must manufacture the initial density by hand because no channel can outrun an empty product. TRIGGER: A spec for a feed, map, marketplace, roster, leaderboard, directory, team view, or any social surface, with no stated plan for what a first user or solo user sees.
- **The Big-Bang Relaunch** — Replacing a shipped surface wholesale in one release couples a hundred independent bets into a single irreversible event, so you cannot tell which change caused the loss, and existing users pay the full re-learning cost on a day they did not choose. Habitual users are the ones who notice most, and they are the ones you can least afford to lose. TRIGGER: A plan replaces an existing shipped surface in one release — 'v2 replaces v1', 'retire the old frame', 'cut over' — with no dual-run, opt-in, or staged migration.
- **The Never-Restarted Subsystem** — Long-lived services grow past the scale their cold-start path was designed for, and because that path never runs, the regression is invisible until the day you need it. Recovery time then becomes an unknown discovered during the outage. TRIGGER: A design involving a long-lived stateful service, cache, or index, where warm-up, rebuild, replay, or cold-start time is unstated or assumed fast.
- **Piggyback Channel Ignored** — Early on you cannot afford to create demand, only to intercept it, which means the cheapest first channel is wherever your users are already aggregated and transacting. Teams skip this because owned channels (blog, newsletter, own social account) feel more legitimate — but those start at zero audience and compound too slowly to survive the runway. TRIGGER: A GTM plan whose channel list contains only owned surfaces (own blog, own newsletter, own social account, own docs site) and names no existing venue, marketplace, forum, or community where the target users already gather.
- **Product Line Sprawl** — Each additional surface, SKU, or entry point consumes maintenance, documentation, support, and decision bandwidth permanently, while the marginal one is almost always worse than the median — so average quality falls monotonically as count rises, and the team's best people are spread across things no one would start today. TRIGGER: The plan adds a new surface, product, SKU, CLI command, MCP tool, page, or entry point while existing ones are unfinished, unowned, or undocumented; a countable surface inventory grows.
- **The Great Rewrite** — A rewrite discards the accumulated bug fixes encoded in the old code — each ugly branch is a defect someone found in production — while the old system keeps needing maintenance, so the team pays for two systems and ships neither. TRIGGER: A prompt or issue proposing to "rewrite from scratch", "start clean", "greenfield it", or replace a working subsystem wholesale because the code is messy.
- **The Inside-View Estimate** — An estimate built by decomposing the specific task counts only the steps you can currently see, and the steps you cannot see are exactly the ones that consume the schedule. Decomposition feels more rigorous than a base rate, so it displaces the base rate rather than being checked against it. TRIGGER: A plan, spec, or roadmap states a duration, ship date, or phase count derived by listing the work, with no reference to how long a comparable past effort actually took.
- **Adding People To A Late Thing** — New people on a late project consume the time of the people who know the system, and communication paths grow quadratically with headcount, so the near-term effect on a component with tight internal coupling is negative. Partitionable work is the exception, and the work that is late is rarely the partitionable kind. TRIGGER: A slipping deliverable is answered by assigning more engineers, more parallel agents, or more concurrent sessions to the same component or file set, rather than by cutting scope.
