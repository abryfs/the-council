# p12

**Prompt the founder typed:**
> what's the right postgres index for `WHERE team_id = $1 AND created_at > $2 ORDER BY created_at DESC LIMIT 50`? composite or two separate?

_Context: Mechanical database question during a feature build_

For EACH set below, judge EACH pattern: is it genuinely relevant to this specific prompt — would surfacing it change or improve how an agent handles this request? Be strict. A pattern that is merely topically adjacent is NOT relevant.


## Set A

- **Org Chart Shipped To Users** — A split that mirrors an internal boundary — separate app, brand, login, repo, or team — makes users pay the cost of a structure that exists for the builders' convenience. Users experience one job; splitting it forces them to re-onboard into a second product to accomplish what was previously one motion. TRIGGER: A split, rename, or separation in the product mirrors an internal boundary (two teams, two repos, two services, two panes) and forces the user to move between surfaces to complete one task.
- **Distributed Monolith** — Splitting a codebase into services that share a release cadence and shared libraries converts in-process function calls into network calls without decoupling deploys, so you pay partial-failure, latency, and operational cost while keeping every coupling you had. TRIGGER: A spec proposing a separate service, worker, repo, or deployable per entity/destination/integration, or a diff introducing an RPC boundary between two things that ship together.
- **Interface Without A Contract** — When two components exchange bare numbers or strings, the meaning (unit, timezone, encoding, ID namespace) lives only in each side's head. Nothing at the boundary can detect disagreement, so the mismatch propagates as plausible-looking data instead of an error. TRIGGER: A new API field, event payload, or cross-team/cross-service boundary passing raw numbers, timestamps, identifiers, or strings with no shared type, unit, or validation at the boundary.
- **The Never-Restarted Subsystem** — Long-lived services grow past the scale their cold-start path was designed for, and because that path never runs, the regression is invisible until the day you need it. Recovery time then becomes an unknown discovered during the outage. TRIGGER: A design involving a long-lived stateful service, cache, or index, where warm-up, rebuild, replay, or cold-start time is unstated or assumed fast.
- **Cofounder Equity Without Vesting** — Equity granted without vesting or a cliff prices a contribution before it has happened, and the grant survives the contributor's departure, disagreement, or non-performance. The dispute surfaces at the financing or acquisition that makes the equity worth litigating, which is the worst possible moment to have it. TRIGGER: A cofounder split, advisor grant, contractor equity arrangement, or early-employee offer is described with a percentage but no vesting schedule, cliff, or repurchase right.
- **Foundation Before First User** — Infrastructure built for a feature that does not exist has no consumer to falsify its design, so its interface is derived from imagination and calcifies before contact. The dependent feature then inherits constraints from a substrate that was never tested against the real requirement. TRIGGER: A spec adds infrastructure — an index, cache, schema, consolidation pass, worker, centroid set, router — whose only named consumer is a feature not yet built or validated.
- **Guessing The Bottleneck** — Intuition about performance is trained on the code you read, while cost lives in behavior you cannot see — allocation, cache misses, scheduler and GC intervals, tail latency. Optimizing before profiling spends effort on the wrong axis and hides the real cause behind a changed baseline. TRIGGER: A diff or plan doing performance work — caching, batching, async, index, language/runtime swap — with no profile, benchmark, or production measurement cited, or a claim that something "should be faster".
- **The Great Rewrite** — A rewrite discards the accumulated bug fixes encoded in the old code — each ugly branch is a defect someone found in production — while the old system keeps needing maintenance, so the team pays for two systems and ships neither. TRIGGER: A prompt or issue proposing to "rewrite from scratch", "start clean", "greenfield it", or replace a working subsystem wholesale because the code is messy.
- **Accessibility As Post-Ship Bug** — Accessibility is decided by structure — semantics, focus order, names, contrast — which is fixed at the moment the component is built; deferring it converts a design constraint into a rewrite, and in many jurisdictions into legal exposure that no backlog priority can defer. TRIGGER: A spec or diff ships an interactive component with a11y noted as follow-up, or introduces custom interactive markup (div-as-button, custom modal, canvas UI, drag-and-drop) with no keyboard path, focus management, or accessible name.
- **No Beachhead** — A message aimed at everyone is specific to no one, so it fails the only test that matters early: can one user explain it to the next user in a sentence. Without a defined first customer, price, channel, and objection-handling all become guesses, and there is no dense population in which word of mouth can propagate. TRIGGER: TAM-driven sizing, "for any team / any company / everyone who...", or a launch plan listing three or more personas with no ranking of which one ships first.
- **Seat Pricing Punishes Adoption** — When a product's value rises with how many colleagues are on it but the price also rises per colleague, the buyer's rational move is to restrict the rollout — which starves the exact network effect the product depends on. The pricing model actively fights the product's mechanism, and the resulting low penetration reads to the team as weak demand. TRIGGER: A pricing page or spec charging per seat, per user, or per member for a product whose core value requires a whole team, or charging full price for read-only/viewer/observer roles.
- **Innovation Token Overdraft** — Every unfamiliar technology carries unknown failure modes that only surface under production load, and each one consumes the same scarce resource: engineer attention during incidents. Spending several at once means every outage has multiple novel suspects and no one has intuition about any of them. TRIGGER: A diff or spec that introduces a new datastore, language, queue, or orchestration layer — especially two or more in the same change — where an already-running component would do.
- **Silent Room Consensus** — Silence in a decision meeting is recorded as agreement, but it is more often the cost of dissent exceeding its expected payoff — one person's objection cannot beat an apparently settled room, so no one pays. The group then treats the absence of objection as independent corroboration it never received. TRIGGER: A prompt or doc asserts "the team is aligned", "no objections were raised", or "we all agreed" without naming a specific person who argued the other side and what they said.
- **Hype Ahead Of Usability** — A long, expert-narrated demo can make an unexplainable product look compelling to an audience primed to be impressed, and invite scarcity converts that impression into signups. Neither tests the actual constraint — whether one ordinary user can explain the product to the next one — so the waitlist converts into a cohort that opens it once and never returns. TRIGGER: A launch plan gated by waitlist or invite codes, or a demo script/video longer than about two minutes that requires narration to make the product legible.
- **Metaphor Fusion** — A product that fuses several familiar categories inherits none of their mental models, so a new user has no prior to fall back on and no one-sentence description to pass along; adoption then depends on formal explanation, which does not travel. TRIGGER: A spec describes the surface by joining categories with "and" ("it's a doc and a chat and a board"), unifies two existing product surfaces into one, or cannot state what the thing is in one sentence a non-user would repeat.

## Set B

- **Adding People To A Late Thing** — New people on a late project consume the time of the people who know the system, and communication paths grow quadratically with headcount, so the near-term effect on a component with tight internal coupling is negative. Partitionable work is the exception, and the work that is late is rarely the partitionable kind. TRIGGER: A slipping deliverable is answered by assigning more engineers, more parallel agents, or more concurrent sessions to the same component or file set, rather than by cutting scope.
- **Statistics Against Trust** — Answering a reported defect with its probability treats the user's problem as frequency when the actual damage is to the belief that the product's outputs can be relied on without checking. The probability argument is usually correct and always escalates, because it tells the reporter their experience does not count. TRIGGER: A response to a user-reported bug, data-loss report, or wrong-output complaint leads with how rare the condition is, or proposes closing it as won't-fix on frequency grounds.
- **The Metric Becomes The Job** — Tying reward to a single countable output makes the cheapest path to the number, not the outcome, the rational behavior for everyone measured — and the cheapest path is usually fabrication or reclassification. The metric keeps improving while the thing it proxied for degrades, and the metric is the only instrument you have. TRIGGER: A spec, OKR, or plan ties compensation, ranking, or a pass/fail gate to a single countable output (accounts, PRs merged, tickets closed, coverage percent, broadcasts sent).
- **One-Way Door Misread** — Anything external parties can build against — a public API, tool name, URL scheme, event type, wire field, file format — becomes unrevocable the moment someone depends on it, because the cost of removal is paid by them and shows up as broken trust rather than a rollback. Such decisions get made at the speed of a reversible one because the diff looks small. TRIGGER: A diff or spec publishes something external parties will depend on: a public API endpoint, an MCP or CLI tool name, an event type or enum value, a URL scheme, a config key, an on-disk or wire format.
- **Premature Platformization** — A protocol, plugin API, or generality invented before one concrete use is in production is designed against imagined consumers, so it optimizes for flexibility no one needs while missing the constraint the first real user would have imposed. It also raises the cost of every subsequent change, because generality is what you promise not to break. TRIGGER: A spec introduces a protocol, plugin API, extension point, federation model, or abstraction justified by future third parties ('so others can build on it', 'generic enough for N cases') before one concrete case is in production.
- **No Beachhead** — A message aimed at everyone is specific to no one, so it fails the only test that matters early: can one user explain it to the next user in a sentence. Without a defined first customer, price, channel, and objection-handling all become guesses, and there is no dense population in which word of mouth can propagate. TRIGGER: TAM-driven sizing, "for any team / any company / everyone who...", or a launch plan listing three or more personas with no ranking of which one ships first.
- **Announcing The Successor** — Publicly declaring the current product inferior transfers demand to a replacement that does not yet exist, so the revenue collapses before the substitute can catch it. The honesty is real and the timing makes it self-inflicted. TRIGGER: Customer-facing copy, changelog, docs, or a public roadmap describes a currently shipping product, framing, or API as deprecated, weak, or superseded before its replacement is available.
- **Sunk Identity** — A decision defended by prior investment or by "this is what we are" cannot be evaluated, because both premises are facts about the past rather than about the option. The incumbent option gets an unearned advantage precisely in proportion to how much was spent establishing it. TRIGGER: A decision or spec is defended by how much has already been built, how long it took, or by identity language ("we're a X company", "this is our thesis"), rather than by the option's forward value.
- **The Approval Bottleneck** — Centralizing a recurring decision in one person converts a throughput problem into a queue whose depth is invisible to the approver, who sees only the items they touched. Quality rises per item while the volume of items that never arrive — because the wait killed them — goes unmeasured. TRIGGER: A process or spec routes every instance of a recurring decision (hires, merges, deploys, copy changes, place bindings) through one named approver, with no delegation rule or bypass condition.
- **Technology Seeking A Job** — When the differentiator is stated as a capability rather than a task someone was already trying to accomplish, the feature has no natural moment of use, so adoption requires teaching a new behavior instead of intercepting an existing one. Impressive capability and unused capability are fully compatible. TRIGGER: The spec leads with what the system can do ('we can embed / route / render / detect X') and the user's task appears only as a downstream illustration, or a hero feature has no named moment when someone would reach for it.
- **Distribution As An Afterthought** — Product work has a legible feedback loop (ship, see it work) and distribution does not, so engineering-led teams spend the entire runway on the loop that feels productive and reach the market with no channel built. By the time distribution becomes urgent, the money that would have funded channel experiments is already spent on the product. TRIGGER: A roadmap, spec, or milestone list where every item is a product capability and no item names a specific acquisition channel, or a plan that says marketing/launch/GTM happens "after v1".
- **Numbers Nobody Measured** — A quantitative claim with no measurement behind it still functions as one downstream — it gets cited, budgeted against, and used to close arguments — because the number's format carries authority its provenance does not. Organizations generate these numbers where the desired answer is known and the measurement is expensive. TRIGGER: A spec, README, or marketing line quotes a reliability, latency, uptime, accuracy, or coverage figure without naming the measurement that produced it.
- **Refusing The Amputation** — Deferring a feature to 'phase 2' keeps it in the architecture — its data model, its surface area, its coupling — so the v1 carries the full complexity cost while delivering none of the value. Deletion is the only scope cut that actually reduces work; deferral is bookkeeping. TRIGGER: A v1 spec preserves every feature from a prototype or predecessor, and the scope-cut discussion produces deferrals ('phase 2', 'later slice', 'roadmap') rather than removals from the model.
- **Root Cause Singular** — Five-whys terminates at the first cause that is both technical and fixable, because that node is where the search stops feeling productive. The organizational conditions that let the technical fault reach production are upstream of that stopping point, so they survive the fix and reproduce it. TRIGGER: An incident writeup, postmortem, or bug analysis names exactly one root cause and one code-level fix, with no finding about how the defect passed review or shipped.
- **Funding As Distribution** — A funding announcement and its press cycle produce a one-time spike of curious non-customers, which the team reads as demand and uses to justify skipping channel-building. Press has no compounding mechanism — it cannot be re-run — so the traffic decays to zero while the burn rate raised to match the ambition does not. TRIGGER: A launch plan whose top-of-funnel is press coverage, a funding announcement, an influencer/analyst push, or a Product Hunt / HN / Show HN day, with no channel that keeps producing users on day 30.

## Set C

- **Guessing The Bottleneck** — Intuition about performance is trained on the code you read, while cost lives in behavior you cannot see — allocation, cache misses, scheduler and GC intervals, tail latency. Optimizing before profiling spends effort on the wrong axis and hides the real cause behind a changed baseline. TRIGGER: A diff or plan doing performance work — caching, batching, async, index, language/runtime swap — with no profile, benchmark, or production measurement cited, or a claim that something "should be faster".
- **Numbers Nobody Measured** — A quantitative claim with no measurement behind it still functions as one downstream — it gets cited, budgeted against, and used to close arguments — because the number's format carries authority its provenance does not. Organizations generate these numbers where the desired answer is known and the measurement is expensive. TRIGGER: A spec, README, or marketing line quotes a reliability, latency, uptime, accuracy, or coverage figure without naming the measurement that produced it.
- **Reused Component, New Envelope** — A component's correctness depends on the operating envelope it was validated in — value ranges, clock rates, load profile. Reuse carries the code but not the envelope, and the assumption that made it safe becomes silently false. TRIGGER: A diff or plan that lifts an existing module, service, query, or library into a new scale, platform, region, or traffic profile described as reusing it "unchanged" or "as-is".
- **Interface Without A Contract** — When two components exchange bare numbers or strings, the meaning (unit, timezone, encoding, ID namespace) lives only in each side's head. Nothing at the boundary can detect disagreement, so the mismatch propagates as plausible-looking data instead of an error. TRIGGER: A new API field, event payload, or cross-team/cross-service boundary passing raw numbers, timestamps, identifiers, or strings with no shared type, unit, or validation at the boundary.
- **Two-Way Door Deliberated** — Applying heavyweight process to a reversible decision costs more than being wrong would have, and the delay itself removes the cheapest source of information — shipping it and watching. Organizations default to the heavy process for everything because the process was designed around the rare irreversible case. TRIGGER: An easily reversible change — copy, layout, a default value, ordering, a flag's initial setting, a threshold — is escalated to a spec, a review cycle, or a founder decision.
- **Preserving The Shape** — When a change is bolted onto an existing structure specifically to avoid disturbing it — because touching it would trigger a migration, recertification, or retraining cost — the new behavior inherits constraints it was never designed for, and the reason to avoid them becomes a reason not to fix them. TRIGGER: A change explicitly scoped to avoid touching an existing schema, interface, migration, or retraining/re-certification cost — phrases like "without changing the existing", "to avoid a migration", "keep it backward compatible" driving the design rather than following it.
- **Launch Without Load** — Capacity assumptions that are never measured are wrong in the unsafe direction, because designers estimate from the intended usage rather than the arrival pattern. Load appears as a step function at launch, not a ramp, so the first real test is also the first outage. TRIGGER: A ship/launch date with no load or soak test in the plan, or a stated concurrency/throughput number that is an estimate rather than a measurement.
- **Craft On The Wrong Axis** — Engineering and design effort has a fixed budget and no automatic mapping to user-perceived value; teams that measure craft by internal difficulty will pour it into components whose quality is invisible in use, and ship a product whose expensive parts are the ones nobody experiences. TRIGGER: A diff or spec invests heavy effort in something the user never sees, touches, or measures — an internal abstraction, a component's hidden tolerances, a custom build pipeline, a rendering engine — while the user-facing behavior is unchanged.
- **Innovation Token Overdraft** — Every unfamiliar technology carries unknown failure modes that only surface under production load, and each one consumes the same scarce resource: engineer attention during incidents. Spending several at once means every outage has multiple novel suspects and no one has intuition about any of them. TRIGGER: A diff or spec that introduces a new datastore, language, queue, or orchestration layer — especially two or more in the same change — where an already-running component would do.
- **The Never-Restarted Subsystem** — Long-lived services grow past the scale their cold-start path was designed for, and because that path never runs, the regression is invisible until the day you need it. Recovery time then becomes an unknown discovered during the outage. TRIGGER: A design involving a long-lived stateful service, cache, or index, where warm-up, rebuild, replay, or cold-start time is unstated or assumed fast.
- **Chesterton's Dead Code** — Code that appears unused is often reachable through a path nobody has in mind — an old flag, a stale server, a legacy client — so removing the guard while leaving the code, or reusing its switch for a new meaning, arms a landmine that only fires under partial deployment. TRIGGER: A diff that deletes or repurposes a feature flag, retry, guard clause, or branch labeled unused/deprecated/legacy without explaining what originally set it.
- **Alert As The Fix** — Adding a warning to an unactioned stream does not create action; it raises the base rate of ignorable signals, which lowers the probability that any specific one is investigated. The detection exists on paper and is absent in practice. TRIGGER: A proposed remediation that consists of logging a warning, emitting a metric, or adding a monitor — with no owner, threshold, or defined response — or a codebase with existing warnings nobody triages.
- **Trivial Transitive Dependency** — A dependency's risk is set by the reliability of its publishing and maintenance, not by its size, and transitive pulls mean the risky package is one nobody chose. Eleven lines of code can carry the same availability and supply-chain exposure as eleven thousand. TRIGGER: A diff adding a package to package.json, go.mod, requirements.txt, or Cargo.toml — especially a small single-purpose one, or one arriving transitively rather than being chosen.
- **Distributed Monolith** — Splitting a codebase into services that share a release cadence and shared libraries converts in-process function calls into network calls without decoupling deploys, so you pay partial-failure, latency, and operational cost while keeping every coupling you had. TRIGGER: A spec proposing a separate service, worker, repo, or deployable per entity/destination/integration, or a diff introducing an RPC boundary between two things that ship together.
- **Pet Cluster Upgrade** — Infrastructure configured by hand and not committed anywhere has no record of what depends on what, so an upgrade that changes an implicit contract (a label, a default, a deprecated field) breaks something nobody can trace back. Recovery becomes archaeology under time pressure. TRIGGER: An in-place upgrade, version bump, or migration of infrastructure described as legacy, hand-built, one-off, or "the original" — or config applied manually rather than from version control.
