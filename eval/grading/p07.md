# p07

**Prompt the founder typed:**
> convert the callbacks in lib/uploader.js to async/await. keep the error semantics identical.

_Context: Routine refactor, callback-style legacy module_

For EACH set below, judge EACH pattern: is it genuinely relevant to this specific prompt — would surfacing it change or improve how an agent handles this request? Be strict. A pattern that is merely topically adjacent is NOT relevant.


## Set A

- **Guessing The Bottleneck** — Intuition about performance is trained on the code you read, while cost lives in behavior you cannot see — allocation, cache misses, scheduler and GC intervals, tail latency. Optimizing before profiling spends effort on the wrong axis and hides the real cause behind a changed baseline. TRIGGER: A diff or plan doing performance work — caching, batching, async, index, language/runtime swap — with no profile, benchmark, or production measurement cited, or a claim that something "should be faster".
- **Error Text From Inside** — A message written from the system's state names a condition the user has no model for and no action attached to; it is technically accurate and operationally useless, so the user's only remaining move is to ask a human or abandon the task. TRIGGER: A diff adds or changes user-visible error, empty, or status copy that names an internal condition (state names, error codes, subsystem names, exception text) instead of what failed plus one concrete action the user can take.
- **Preserving The Shape** — When a change is bolted onto an existing structure specifically to avoid disturbing it — because touching it would trigger a migration, recertification, or retraining cost — the new behavior inherits constraints it was never designed for, and the reason to avoid them becomes a reason not to fix them. TRIGGER: A change explicitly scoped to avoid touching an existing schema, interface, migration, or retraining/re-certification cost — phrases like "without changing the existing", "to avoid a migration", "keep it backward compatible" driving the design rather than following it.
- **Curated Demo Data** — Designs validated on hand-picked content encode assumptions about length, density, freshness, and correctness that real data violates on day one; the demo proves the layout, not the product, and the gap surfaces publicly at launch scale. TRIGGER: A design, screenshot, or demo uses seeded, curated, or short sample data; or a spec has no defined empty state, long-string, stale-data, error, and high-volume case for the surface being built.
- **Unlabeled Working Surface** — Surfaces "no user sees" — shell prompts, admin panels, log output, internal dashboards — are used by humans under time pressure, and identical-looking contexts there produce identity confusion at the exact moment stakes are highest. Unseen does not mean unused; it means untested. TRIGGER: Work touches an internal-only surface — CLI output, shell/SSH tooling, admin console, staging vs prod environment, log lines, migration scripts — and the change is justified as "internal, no design needed."
- **Accessibility As Post-Ship Bug** — Accessibility is decided by structure — semantics, focus order, names, contrast — which is fixed at the moment the component is built; deferring it converts a design constraint into a rewrite, and in many jurisdictions into legal exposure that no backlog priority can defer. TRIGGER: A spec or diff ships an interactive component with a11y noted as follow-up, or introduces custom interactive markup (div-as-button, custom modal, canvas UI, drag-and-drop) with no keyboard path, focus management, or accessible name.
- **Undifferentiated Price War** — Competing on a dimension your rival can copy within a week converts the whole category's margin into customer subsidy, and both sides must keep spending to hold position they can never win. The winner is whoever has more capital, not whoever built the better product. TRIGGER: The plan competes on price, free-tier size, limits, discounting, or speed of copying a feature, in a market where a funded competitor can match the move immediately.
- **Wartime Frame In Peacetime** — Consensus-building, broad exploration, and process are correct when the constraint is opportunity and wrong when the constraint is survival — and vice versa. Teams keep whichever mode they last succeeded in, so the mismatch persists exactly through the period where it is most expensive. TRIGGER: An existential condition is stated (runway, a competitor shipping the core feature, a broken primary flow, zero users) and the proposed response is a broad multi-track plan, a process change, or a round of alignment.
- **Interface Without A Contract** — When two components exchange bare numbers or strings, the meaning (unit, timezone, encoding, ID namespace) lives only in each side's head. Nothing at the boundary can detect disagreement, so the mismatch propagates as plausible-looking data instead of an error. TRIGGER: A new API field, event payload, or cross-team/cross-service boundary passing raw numbers, timestamps, identifiers, or strings with no shared type, unit, or validation at the boundary.
- **Fixed Date Beats Evidence** — When a date is set by an external event rather than by the work, evidence that the work needs longer has nowhere to go — it can only be reframed as pessimism or vendor cover. The date is unfalsifiable, so the scope silently absorbs the error and the failure arrives after the date instead of before it. TRIGGER: An immovable external date (launch event, conference demo, investor meeting, contract deadline) is stated, and someone with direct prior experience of the same work says the schedule is short.
- **Boiling The Ocean** — When v1 requires three or more unproven components to all work at once, the probability of shipping is the product of each part's odds, and no single part can be validated until the others exist. Learning is deferred until the whole thing is done, which is exactly when it is most expensive to be wrong. TRIGGER: A spec or plan lists three or more novel, unproven components (new runtime, new data model, new rendering surface, new protocol) that must all work before anything is usable.
- **The Big-Bang Relaunch** — Replacing a shipped surface wholesale in one release couples a hundred independent bets into a single irreversible event, so you cannot tell which change caused the loss, and existing users pay the full re-learning cost on a day they did not choose. Habitual users are the ones who notice most, and they are the ones you can least afford to lose. TRIGGER: A plan replaces an existing shipped surface in one release — 'v2 replaces v1', 'retire the old frame', 'cut over' — with no dual-run, opt-in, or staged migration.
- **Second-System Rewrite** — A rewrite is scoped against the accumulated wishlist of everything the old system got wrong, so the new system is strictly larger than the one that already took years. Meanwhile the old system keeps shipping nothing, and the rewrite's real cost is the undocumented edge cases embedded in the code being discarded. TRIGGER: A proposal to rewrite a working module or surface from scratch, justified by cruft, where the new version is also scoped to fix known limitations of the old one.
- **Foundation Before First User** — Infrastructure built for a feature that does not exist has no consumer to falsify its design, so its interface is derived from imagination and calcifies before contact. The dependent feature then inherits constraints from a substrate that was never tested against the real requirement. TRIGGER: A spec adds infrastructure — an index, cache, schema, consolidation pass, worker, centroid set, router — whose only named consumer is a feature not yet built or validated.
- **Technology Seeking A Job** — When the differentiator is stated as a capability rather than a task someone was already trying to accomplish, the feature has no natural moment of use, so adoption requires teaching a new behavior instead of intercepting an existing one. Impressive capability and unused capability are fully compatible. TRIGGER: The spec leads with what the system can do ('we can embed / route / render / detect X') and the user's task appears only as a downstream illustration, or a hero feature has no named moment when someone would reach for it.

## Set B

- **Chasing The Moving Baseline** — Rescoping in-flight work to adopt a newer substrate resets the completion clock while the substrate keeps advancing, so the gap between what you have and what is current never closes — each adoption is individually justified and the sequence never terminates. TRIGGER: In-flight work is rescoped to adopt a newly released model, framework, engine, API version, or internal abstraction before the current version has shipped to anyone.
- **The Great Rewrite** — A rewrite discards the accumulated bug fixes encoded in the old code — each ugly branch is a defect someone found in production — while the old system keeps needing maintenance, so the team pays for two systems and ships neither. TRIGGER: A prompt or issue proposing to "rewrite from scratch", "start clean", "greenfield it", or replace a working subsystem wholesale because the code is messy.
- **Cold Start Ignored** — Any product whose value comes from other people's content or presence is worthless to user one, so the acquisition funnel and the retention mechanism fight each other: every user you bring sees an empty room and leaves, and their departure makes the room emptier. The founders must manufacture the initial density by hand because no channel can outrun an empty product. TRIGGER: A spec for a feed, map, marketplace, roster, leaderboard, directory, team view, or any social surface, with no stated plan for what a first user or solo user sees.
- **Piggyback Channel Ignored** — Early on you cannot afford to create demand, only to intercept it, which means the cheapest first channel is wherever your users are already aggregated and transacting. Teams skip this because owned channels (blog, newsletter, own social account) feel more legitimate — but those start at zero audience and compound too slowly to survive the runway. TRIGGER: A GTM plan whose channel list contains only owned surfaces (own blog, own newsletter, own social account, own docs site) and names no existing venue, marketplace, forum, or community where the target users already gather.
- **Commit Without Disagreeing** — An unrecorded disagreement does not disappear; it re-emerges as slow execution, quiet re-litigation, and a preserved right to say "I never liked this" when the result is bad. Writing the disagreement down before committing is what converts a private hedge into a shared bet. TRIGGER: A decision is recorded with unanimous support and then reopened, slow-walked, or partially implemented; or a teammate agrees to a plan in one message and questions its premise in a later one.
- **Guessing The Bottleneck** — Intuition about performance is trained on the code you read, while cost lives in behavior you cannot see — allocation, cache misses, scheduler and GC intervals, tail latency. Optimizing before profiling spends effort on the wrong axis and hides the real cause behind a changed baseline. TRIGGER: A diff or plan doing performance work — caching, batching, async, index, language/runtime swap — with no profile, benchmark, or production measurement cited, or a claim that something "should be faster".
- **Channel-Price Mismatch** — A product's price point determines which acquisition channels can ever pay back; ad-based channels have a floor CAC set by auction competition, and if that floor exceeds the customer's lifetime contribution the channel is unusable at any spend level. Teams discover this after burning the test budget because they benchmarked click-through, not payback. TRIGGER: A GTM plan or budget line proposing Google/Meta/LinkedIn/Reddit ads, sponsorships, or outbound SDRs without stating ARPU, gross margin, and a payback period in months.
- **Boiling The Ocean** — When v1 requires three or more unproven components to all work at once, the probability of shipping is the product of each part's odds, and no single part can be validated until the others exist. Learning is deferred until the whole thing is done, which is exactly when it is most expensive to be wrong. TRIGGER: A spec or plan lists three or more novel, unproven components (new runtime, new data model, new rendering surface, new protocol) that must all work before anything is usable.
- **Hype Ahead Of Usability** — A long, expert-narrated demo can make an unexplainable product look compelling to an audience primed to be impressed, and invite scarcity converts that impression into signups. Neither tests the actual constraint — whether one ordinary user can explain the product to the next one — so the waitlist converts into a cohort that opens it once and never returns. TRIGGER: A launch plan gated by waitlist or invite codes, or a demo script/video longer than about two minutes that requires narration to make the product legible.
- **Sunk Identity** — A decision defended by prior investment or by "this is what we are" cannot be evaluated, because both premises are facts about the past rather than about the option. The incumbent option gets an unearned advantage precisely in proportion to how much was spent establishing it. TRIGGER: A decision or spec is defended by how much has already been built, how long it took, or by identity language ("we're a X company", "this is our thesis"), rather than by the option's forward value.
- **Metaphor Fusion** — A product that fuses several familiar categories inherits none of their mental models, so a new user has no prior to fall back on and no one-sentence description to pass along; adoption then depends on formal explanation, which does not travel. TRIGGER: A spec describes the surface by joining categories with "and" ("it's a doc and a chat and a board"), unifies two existing product surfaces into one, or cannot state what the thing is in one sentence a non-user would repeat.
- **Big-Bang Delivery** — When integration is scheduled once at the end, every incorrect assumption compounds silently for the whole project and all of them surface simultaneously, at the moment there is no budget left to act on them. Nothing is falsified until it is too late to be cheap. TRIGGER: A roadmap or plan whose milestones are all internal (design, build, integrate) with a single user-visible cutover at the end, and no shippable increment before it.
- **Job Mistaken For Demographic** — Segmenting by who the user is produces feature requests that correlate with the segment but explain nothing causal, so improvements aimed at the persona miss the situation that actually triggered the purchase. Two people in the same demographic hire the product for opposite jobs, and averaging them produces a product for neither. TRIGGER: Requirements are segmented by who the user is (role, persona, seniority, company size, 'founders vs engineers') rather than by the situation and task at the moment of use.
- **Craft On The Wrong Axis** — Engineering and design effort has a fixed budget and no automatic mapping to user-perceived value; teams that measure craft by internal difficulty will pour it into components whose quality is invisible in use, and ship a product whose expensive parts are the ones nobody experiences. TRIGGER: A diff or spec invests heavy effort in something the user never sees, touches, or measures — an internal abstraction, a component's hidden tolerances, a custom build pipeline, a rendering engine — while the user-facing behavior is unchanged.
- **Technology Seeking A Job** — When the differentiator is stated as a capability rather than a task someone was already trying to accomplish, the feature has no natural moment of use, so adoption requires teaching a new behavior instead of intercepting an existing one. Impressive capability and unused capability are fully compatible. TRIGGER: The spec leads with what the system can do ('we can embed / route / render / detect X') and the user's task appears only as a downstream illustration, or a hero feature has no named moment when someone would reach for it.

TRIGGER: A diff that deletes or repurposes a feature flag, retry, guard clause, or branch labeled unused/deprecated/legacy without explaining what originally set it.

The convenience is opt-out by omission rather than opt-in by intent. TRIGGER: A diff adding a package to package.json, go.mod, requirements.txt, or Cargo.toml — especially a small single-purpose one, or one arriving transitively rather than being chosen.
- **Root Cause Singular** — Five-whys terminates at the first cause that is both technical and fixable, because that node is where the search stops feeling productive. The organizational conditions that let the technical fault reach production are upstream of that stopping point, so they survive the fix and reproduce it.
